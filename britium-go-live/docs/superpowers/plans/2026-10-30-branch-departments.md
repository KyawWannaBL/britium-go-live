# Branch department workspaces

Goal: provide Mandalay with Marketing, BD, Customer Service, Admin/HR, Master Data and Tariff screens, synchronized with the shared head-office system and scoped by active server-side branch identity.

Approach: reuse canonical CRM, CS, employee, HR document, master and tariff records. Branch managers receive dedicated views at the existing module routes; HQ users retain their current pages. Do not duplicate company-wide masters. The user's earlier delegation permits routine implementation decisions without another design approval round.

1. Database tests first: deny other-branch records, forged scope/actors, inactive accounts and unauthorized roles; prove canonical CRM writes, CS history, HR document ownership, master/tariff references and change requests.
2. Scoped RPCs: explicitly stamp branch identity on new Marketing/BD records; create/edit leads and prospects. Shared CS cases use branch-related canonical Way IDs and include messages/status. HR offers branch staff view, profile updates without role/login changes, hiring and employment-change requests, and branch document upload/register. Master data and canonical tariffs remain reference + controlled change request for non-Superadmins, matching existing tariff authority. Audit all mutations; retain HQ visibility.
3. UI: module navigation, search, labelled forms, tables, selected-record details, CS conversation, HR document upload/download, master/tariff request submission and status. All six routes available to branch managers. Show truthful loading/errors, prevent duplicate mutations and stale branch/module responses. HQ Branch Admin shows full proposal details and distinguishes review from application.
4. Verification: synthetic PGlite fixtures and React UI tests, existing role/finance/warehouse regressions, full test/build, independent code review, apply SQL, publish/merge PR and verify the production deployment and live modules.

Constraints: no global role escalation, credential access, company-wide edits, automatic tariff changes, payment authority, live trip reassignment or historical branch inference. Legacy unclassified CRM remains HQ-visible; new branch records are explicitly attributed. No live database snapshots in public test fixtures.

Execution: all six module routes and scoped functions implemented.
